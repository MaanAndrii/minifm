# AMOLED Radio

Прошивка для Waveshare ESP32-S3-Touch-AMOLED-2.16: онлайн-радіо, годинник,
будильники, таймери та диктофон. Керування через сенсорний екран і браузер у
локальній мережі. Вебінтерфейс зберігається в прошивці, зовнішній сервер не потрібен.

## Функції

- До 16 станцій із прямими MP3 та AAC/AAC+ потоками HTTP/HTTPS, регулювання гучності й повторне підключення.
- NTP, київський часовий пояс із літнім часом; апаратний RTC зберігає UTC.
- До 8 будильників: один раз або дні тижня, радіо/локальний сигнал, власна гучність, плавне наростання й відкладання 1–30 хв. Налаштування на пристрої та через веб.
- Локальний сигнал, якщо радіопотік будильника не вдається відтворити; сигнал триває максимум 10 хвилин.
- Таймер зворотного відліку та окремий таймер вимкнення радіо, до 24 годин.
- Диктофон: WAV PCM, 16 кГц / 16 біт / моно, перший вбудований мікрофон; пауза та продовження.
- Записи на microSD, відтворення через внутрішній динамік, завантаження та видалення через браузер.
- Під час запису радіо зупиняється. Будильник/таймер спочатку завершує файл, потім подає сигнал.
- Захищена точка доступу для першого налаштування та відновлення доступу при проблемах Wi-Fi.
- Налаштування й історія спрацьовування будильників у NVS; ключ доступу унікальний для пристрою.
- Шрифт із кирилицею для назв станцій на AMOLED.
- Чотири мінімалістичні екрани, заряд батареї у відсотках, автоповорот і пробудження при піднятті з нічним блокуванням.

## Обладнання та залежності

Цільова конфігурація: ESP32-S3, 16 МБ Flash, 8 МБ Octal PSRAM, BSP Waveshare
`2.0.1`, LVGL `9.3.0`, ESP-IDF `5.5.5`. Залежності фіксує `dependencies.lock`.
Ревізія фізичної плати ще не підтверджена. Перед першим прошиванням звірте
маркування й апаратну сумісність з офіційною схемою.

microSD має бути FAT32; автоматичне форматування вимкнене. Записи розміщуються
в `/recordings`. Приблизний обсяг: 1,92 МБ за хвилину. `.part`-файли після
некоректного завершення відновлюються під час наступного запуску, якщо дані й
файлова система залишилися читабельними. Це не гарантує відновлення після пошкодження FAT.

## Збирання у Windows

Якщо ESP-IDF 5.5.x вже активовано:

```powershell
cd D:\NewsMon\esp32-radio
idf.py set-target esp32s3
idf.py build
```

Також доступні локальні скрипти:

```powershell
.\scripts\Setup.ps1 -Python python
.\scripts\Build.ps1
.\scripts\Build.ps1 -Port COM5 -Flash -Monitor
```

Замініть `COM5` на порт плати. `Setup.ps1` завантажує ESP-IDF та інструменти
в `.tools` усередині проєкту; потрібні Git, Python 3.10+ і доступ до інтернету.
Для встановлених тут інструментів скрипт збірки автоматично активує середовище.

Якщо PowerShell блокує `.ps1`, використайте дозвіл лише для окремого процесу:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\NewsMon\esp32-radio\scripts\Build.ps1" -Port COM5 -Flash -Monitor
```

Оновлення після першого апаратного запуску: усунуто зависання створення UI через
неблокуючий виклик BSP lock. UI тепер чекає mutex адаптера та перевіряє його результат.

## Перший запуск

1. Вставте microSD, якщо потрібен диктофон, та запустіть пристрій.
2. На екрані годинника утримайте палець понад 1,2 секунди або утримайте клавішу GPIO18 понад секунду, щоб показати ключ доступу. Перші 16 символів — пароль Wi-Fi точки доступу.
3. Підключіться до `AMOLED-Radio-XXXX`, відкрийте `http://192.168.4.1`.
4. Введіть повний вебключ із 32 символів: два рядки на екрані без пробілів.
5. На вкладці «Налаштування» збережіть SSID і пароль домашньої Wi-Fi мережі,
   потім перезапустіть пристрій. Під час активного запису перезапуск заблоковано.
6. Відкрийте IP-адресу, показану на AMOLED. Додайте прямі URL радіопотоків.
7. Налаштуйте будильники та перевірте короткий таймер і тестовий запис.

Якщо пристрій не підключився до Wi-Fi, через 30 секунд запускається резервна
точка доступу. При порожньому полі нового пароля поточний пароль зберігається;
для відкритої мережі встановіть відповідний прапорець.

## Керування на пристрої

Угорі екрана показано Wi-Fi (білий значок — з’єднання, сірий — слабкий сигнал, `AP` — точка доступу, `x` — немає з’єднання), батарею із зарядом у відсотках та USB-живлення. Блискавка означає заряджання. Без батареї її значок прихований; `?` означає недоступні дані. Низький заряд позначено червоним. Дані AXP2101 зчитуються без зміни параметрів заряджання чи живлення.

Пауза радіо закриває потік і декодер, зберігаючи станцію. Повторне натискання створює нове з’єднання з поточним прямим ефіром. Завершення поточного мережевого читання може зайняти до встановленого тайм-ауту (1,5 секунди).

- Свайп ліворуч/праворуч: годинник, радіо, найближчий будильник, таймер.
- Торкання будильника відкриває прокручуваний список із 8 записів. Редактор: час та увімкнення → один раз/дні тижня → локальний сигнал/станція → власна гучність, наростання 0–120 с та відкладання 1–30 хв. Зміни застосовуються лише кнопкою «Зберегти».
- Торкання таймера відкриває вибір «Відлік»/«Сон». Основне налаштування — велике значення хвилин із кнопками «−»/«+» та пресетами 5/15/30 хв; утримання кнопки повторює зміну. Торкання числа відкриває точні години/хвилини/секунди: обирається одна одиниця й змінюється тим самим способом. Кнопка «Назад» зберігає чернетку, «Старт» запускає. Активний відлік відкриває великий залишок часу, паузу/продовження та скасування; повтор доступний у меню таймерів. Після сигналу відновлюється попереднє радіо, зокрема його стан паузи. Таймер сну зменшує гучність протягом останніх 30 секунд.
- На радіо натискання: відтворення/пауза. Свайп вгору/вниз: наступна/попередня станція; у правій чверті екрана: гучність ±5%.
- GPIO18: коротке натискання — відтворення/пауза, утримання понад секунду — ключ доступу.
- BOOT (GPIO0): коротке натискання — наступний екран, утримання — головний екран.
- У редакторі BOOT повертає на попередній крок; утримання закриває редактор без збереження. GPIO18 у редакторі не перемикає радіо.
- Під час сигналу дотик або клавіша відкладає будильник на заданий час; утримання вимикає його. Для таймера коротке натискання вимикає сигнал.
- Через 20 секунд без дій яскравість зменшується, через 60 — стає нульовою. Перший дотик або натискання лише пробуджує екран. Радіо й будильники продовжують працювати.
- QMI8658 працює з акселерометром ±2g у режимі 21 Гц, без гіроскопа. Стабільний нахил протягом 0,5 с повертає зображення та координати дотику. На плоскій поверхні напрямок зберігається; під час дотику чи редагування поворот відкладається.
- Панель залишається у штатному напрямку. Частковий RGB565-кадр повертається програмно в наявному буфері 480×16, точно зворотно до перетворення дотику LVGL. Додано лише 960 байтів для обходу пікселів; новий кадровий або DMA-буфер не виділяється.
- Підняття після нерухомого положення відкриває годинник на 15 с; дотик повертає звичайний тайм-аут 60 с. За замовчуванням рух не пробуджує екран із 23:00 до 07:00 або до отримання правильного часу. У вебналаштуваннях можна змінити нічний інтервал, вимкнути ці функції та задати поправку осей датчика 0/90/180/270°. Фізичну орієнтацію й чутливість потрібно перевірити на платі.
- Налаштування формату v1 автоматично переносяться у v2 зі збереженням мережі, вебключа, станцій та будильників. Невідомий формат не перезаписується.
- Розробку диктофону призупинено; на екрані його керування приховане.

## Перевірки прошивки

- `tests/controller_test.c`: справжній контролер із тестовими годинником/NVS — пауза/повтор таймера, відновлення радіо, гучність, відкладання, одноразовий сигнал, таймер сну та відкат невдалого збереження.
- `tests/time_motion_test.c`: перенесення налаштувань v1, нічні інтервали та фільтрація підняття/чотирьох орієнтацій.
- `tests/display_rotation_test.c`: збіг кожного пікселя та координат дотику в чотирьох орієнтаціях, включно з вузькими, високими та крайовими ділянками.
- `scripts/test_lvgl.py`: нативний TinyCC і справжні форми LVGL 480×480, перевірка меж кнопок, збереження/скасування редактора; рендери у `.tools/screenshots/device-*.ppm`.

- `tests/core_test.c`: календар будильників, захист від повторного спрацьовування
  при поверненні часу назад, перевірка імен файлів, структура WAV.
- `tests/web_test.cjs`: формат таймера, валідація тривалості, команди API,
  заголовок авторизації, обробка помилки доступу. Запуск: `node tests/web_test.cjs`.
- C-тести можна виконати будь-яким локальним C-компілятором:
  `cc -I main tests/core_test.c main/core.c -o core_test`, потім `./core_test`.
- `tests/browser_test.cjs`: мобільний макет і взаємодія з тестовим API через
  Playwright. Перевіряє вхід, станції, будильники, таймер і список записів;
  це симуляція інтерфейсу, а не тест апаратної частини.

Обов’язкова перевірка на фізичній платі: дисплей/сенсор, динамік, канал мікрофона,
microSD, Wi-Fi, реальні потоки, запис при повній карті, завершення запису перед
будильником, RTC після вимкнення, тривала робота без інтернету.

## Межі першої версії

- Радіо: MP3 та AAC-LC/HE-AAC/HE-AACv2 (AAC+) у прямому ADTS-потоці. HLS, M3U/PLS, назви композицій та ICY-метадані поки не підтримуються.
  Сервер, який примусово надсилає ICY-метадані попри `Icy-MetaData: 0`, відхиляється.
- Перемикання аудіо під час мережевого запиту може затриматися приблизно на тайм-аут запиту.
- Bluetooth-аудіо потребує окремого A2DP-передавача; його драйвер не реалізовано.
- Таймери та відкладання не зберігаються після перезапуску; будильники зберігаються.
- Історія спрацьовувань запобігає повтору того самого будильника в той самий
  календарний день. Після навмисного переведення дати назад він відновить роботу,
  коли дата перевищить збережений день. Редагування конкретного будильника скидає його історію.
- HTTP для локальної мережі, без TLS на вебсервері, без OTA.
- Список у браузері показує максимум 256 записів за одне читання.
- RTC потребує живлення для збереження часу; це слід перевірити на вашій ревізії.
